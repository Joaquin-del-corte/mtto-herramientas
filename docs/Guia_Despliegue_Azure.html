Guía de despliegue en Azure

App de Mantenimiento de Herramientas · Static Web Apps + Azure Functions + Azure SQL · con login propio

Al terminar tendrás una URL (ej. https://mantenimiento.azurestaticapps.net) que tu equipo abre desde el celular, entra con usuario y contraseña, y todo queda en tu Azure. La app y su API se publican juntas: no hay claves que pegar en el archivo.

Los archivos que vas a desplegar

Manténlos con esta estructura exacta de carpetas (la carpeta api es la que Azure convierte en el backend):

raíz-del-proyecto/ ├─ index.html (la app) ├─ sw.js (modo sin señal) ├─ staticwebapp.config.json (rutas) └─ api/ ├─ host.json ├─ package.json └─ src/ ├─ index.js (API: login, datos, permisos) ├─ dal.js (acceso a Azure SQL) └─ catalog.js (catálogo + datos de ejemplo) (db_azure_sql.sql va aparte: se ejecuta en la base, no se despliega)
🔐 Nunca pongas contraseñas ni el secreto dentro de estos archivos. Van en la configuración de Azure (Parte D). El código los lee desde ahí.

Parte A — Crear la base de datos (Azure SQL)

1En el Portal de Azure → Create a resource → busca Azure SQL → SQL Database → Create.
2Elige tu suscripción y crea (o elige) un Resource group (ej. rg-mantenimiento). Nombre de base: mantenimiento.
3En Server → Create new: nombre único (ej. sql-mantenimiento-sur), región cercana, y Authentication method = Use SQL authentication. Define un Server admin login (ej. adminsql) y una contraseña fuerte. Anótalas: son las que irán en la configuración.
4En Compute + storage, para costo mínimo elige General Purpose → Serverless (se pausa sola y hay una capa gratuita mensual) o Basic. Crea el recurso y espera a que termine.
5Permitir el acceso. Abre el servidor SQL (no la base) → Networking → en Firewall rules activa “Allow Azure services and resources to access this server” y guarda. Esto deja que las Functions se conecten. Para el paso siguiente, agrega también tu IP actual (Add your client IPv4 address).

Parte B — Crear las tablas

1Abre la base de datos mantenimiento → Query editor (preview) en el menú lateral → inicia sesión con el admin SQL y contraseña de la Parte A.
2Abre el archivo db_azure_sql.sql, copia todo su contenido, pégalo y pulsa Run. Debe decir Query succeeded. (No inserta datos; la API los crea sola en el primer ingreso.)

Parte C — Publicar la app (Static Web App)

La forma estándar y repetible es conectar un repositorio de GitHub; Azure compila y publica solo cada vez que actualices. (Si tu empresa usa Azure DevOps, la lógica es igual con un pipeline.)

1Sube los archivos (con la estructura de arriba) a un repositorio de GitHub — privado está bien.
2Portal de Azure → Create a resource → Static Web App → Create. Suscripción y el mismo Resource group. Nombre: mantenimiento. Plan: Free.
3En Deployment: GitHub → autoriza y elige tu repo y rama (main).
4En Build Details:
  • Build Presets: Custom
  • App location: /
  • Api location: api
  • Output location: (déjalo vacío)
5Create. Azure agrega un workflow a tu repo y hace el primer despliegue (2–4 min). Tu URL aparece en la página del recurso (Overview → URL).

Parte D — Conectar la API con la base (configuración/secretos)

Aquí van los datos sensibles, fuera del código.

1Abre tu Static Web App → Settings → Environment variables (o Configuration) → Application settings.
2Agrega estas 5 variables (botón Add por cada una) y guarda:
NombreValor
SQL_SERVERtu servidor, ej. sql-mantenimiento-sur.database.windows.net
SQL_DATABASEmantenimiento
SQL_USERel admin SQL, ej. adminsql
SQL_PASSWORDla contraseña del admin SQL
JWT_SECRETuna frase secreta larga que inventes (30+ caracteres al azar). Firma los tokens de sesión.
💡 Para generar un JWT_SECRET al azar, sirve cualquier cadena larga sin espacios (mezcla de letras, números y símbolos). No la compartas con nadie.
Tras guardar variables, dale a la app un minuto (reinicia la API). Si algo no conecta, revisa que el firewall del servidor SQL tenga activado “Allow Azure services” (Parte A, paso 5).

Parte E — Primer ingreso y puesta a punto

1Abre la URL de tu Static Web App. Verás la pantalla de Iniciar sesión.
2Entra como administrador con las credenciales iniciales:
  • Usuario: admin
  • Contraseña: Admin1234
La app te pedirá cambiar la contraseña de inmediato (obligatorio).
3Se cargan solos los datos de ejemplo (4 usuarios y 45 herramientas). Ve a Personal y crea a tus técnicos reales (o edita los de ejemplo). Al crear una persona, su contraseña inicial es Clave1234 y también deberá cambiarla en su primer ingreso.
4En Inventario ajusta las herramientas, asígnalas a cada técnico y edita sus checklists.
5Comparte la misma URL con el equipo. Cada técnico entra con su usuario y contraseña y ve solo sus herramientas. En el celular pueden usar “Agregar a pantalla de inicio” para que se vea como una app.
🔑 Cambia las contraseñas por defecto. Los usuarios jperez, msoto, rlopez traen la clave Clave1234: bórralos o cámbiales la clave si no corresponden a personas reales. El sistema obliga a cambiar la clave en el primer ingreso, pero no dejes cuentas de ejemplo abiertas.

Preguntas frecuentes

¿Cuánto cuesta?

El Static Web App Free incluye la API (Functions) sin costo. La base de datos es lo único que puede costar: en Serverless con capa gratuita o Basic, es muy bajo (del orden de pocos dólares al mes o menos según uso). No hay costo de servidor aparte.

¿Los técnicos necesitan cuenta de Microsoft?

No. El login es propio (usuario y contraseña que tú administras en la app). Solo tú necesitas el acceso al Portal de Azure para administrar la infraestructura.

¿Se sincroniza al instante?

La app se actualiza automáticamente cada ~15 segundos y al volver a abrirla, además del botón Refrescar. Es prácticamente en vivo, sin servicios extra.

¿Funciona sin señal?

Sí, una vez abierta con conexión. Si se cae la red, el técnico sigue registrando; los cambios se encolan y se sincronizan al volver la señal (verás abajo el aviso “Sin conexión” con el contador de pendientes).

¿Cómo actualizo la app más adelante?

Editas el archivo en el repositorio de GitHub y Azure vuelve a publicar solo. La base de datos y las variables no se tocan.

¿Y si olvido la contraseña de admin?

Se puede restablecer directamente en la base (Query editor) reemplazando el password_hash del usuario admin. Avísame y te paso la instrucción puntual cuando la necesites.

¿Te trancas en algún paso del portal? Escríbeme en qué pantalla estás y lo resolvemos juntos.
